A quality gate is a release decision that stops or pauses promotion when criteria are unmet. Test reports are evidence of what ran. CodeBuild command results, scan thresholds, and CodePipeline approval actions provide the decisions.

### How it works

1. Run checks in CodeBuild and make a failed requirement return an unsuccessful exit code, the number a process returns to its caller. Review `on-failure`: `CONTINUE` advances to the next phase; `ABORT` stops the build on supported EC2 compute.
2. Put cleanup in `finally`, which runs even when a phase command fails. Commands in either block can fail the phase.
3. Collect result files in a buildspec report group. A buildspec is the file that tells CodeBuild which commands to run and which outputs to collect. Export raw test files to S3 for longer retention.
4. For EC2/on-premises deployments, use the CodeDeploy `ValidateService` lifecycle hook, a script run at a defined deployment event, to check application health. Return nonzero on failure.
5. Apply release criteria before promotion, using scan thresholds or manual approval where required.

| Gate | What stops promotion |
|---|---|
| CodeBuild check | A failing command with an enforcing failure policy |
| InspectorScan | A vulnerability count above a configured severity threshold |
| Manual approval | Rejection or no decision within seven days |

`InspectorScan` supports `SourceCodeScan` and `ECRImageScan`. Its count limits are `CriticalThreshold`, `HighThreshold`, `MediumThreshold`, and `LowThreshold`.

For existing CodeGuru Reviewer repository associations, secret detection can identify credentials embedded in code. Replace those hardcoded secrets through Secrets Manager. Since November 7, 2025, new Reviewer repository associations cannot be created.

### Exam cues

- If the question says coverage is below the team's target but the build passes, think a coverage-check command, because generating the report does not encode the team's release rule.
- If the question says an installed EC2 application is unhealthy, think a failing `ValidateService` script, because installation success alone does not establish application health.
- If the question says retain test evidence beyond a month, think export raw results to S3, because the CodeBuild report expires.

### Remember

- CodeBuild test reports expire after 30 days.
- Coverage reports show line and branch coverage; JUnit XML is a supported test result format.
- Manual approval fails without a decision within seven days.
- `on-failure` is unsupported on Lambda compute and reserved capacity.

> **Trap:** A coverage report does not express your required minimum. The coverage check must fail when the release criterion is unmet.
