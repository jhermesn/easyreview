Two ways to share S3 data without opening the bucket: Requester Pays moves the bill to whoever downloads, and presigned URLs give one person temporary access to one object.

### How it works

1. Requester Pays: the owner enables it on the bucket; requesters authenticate and send `x-amz-request-payer` to accept charges.
2. Presigned URL: a backend signs a URL for one object, one HTTP method and an expiry. Successful signing does not prove access; the signer must have permission when the URL is used.
3. Anyone holding the URL can use it until it expires or the signing credentials stop being valid.

### Exam cues

- If the question says others should pay to download shared data, think Requester Pays.
- If the question says temporary access to a private object for users without AWS credentials, think presigned URLs.
- If the question says private content for many users through a CDN, think CloudFront signed URLs or cookies instead.

### Remember

- Requester Pays: requester pays requests and transfer, owner pays storage, no anonymous access.
- Presigned URL: up to 12 hours in the console, 7 days with CLI or SDK, shorter if signed with temporary credentials.

> **Trap:** A presigned URL can't grant more than its creator has. If the signing role lacks `s3:GetObject`, the URL returns 403.
